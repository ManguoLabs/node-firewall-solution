# 机场节点被墙与中转 IP 高可用方案

面向机场运营者的节点被墙、机场节点被墙、机场 IP 被墙、中转 IP 被墙排查与节点防封、高可用线路设计资料。

> 本仓库讨论节点、入口和中转线路的可用性，不是网站域名被墙解决方案，也不承诺“永不被墙”。

## 常见问题

- 节点突然全红，是节点 IP、中转 IP、入口故障还是配置问题？
- 换 IP 后仍然很快失效，应该检查哪些链路特征？
- Reality、VLESS、AnyTLS、Trojan 或 Hysteria2 节点故障是否可以用同一方法判断？
- 如何用多入口、健康检查与故障转移提高机场线路稳定性？

## 适用场景

- 机场节点或入口 IP 频繁失效
- 中转机或中转 IP 反复被封
- 节点批量全红、失联或连接超时
- 需要设计可观测、可切换、可回滚的高可用入口

## 排查思路

先区分 DNS、端口、进程、路由、入口、中转和落地节点，再使用多地点探测确认故障边界。不要仅凭单个客户端失败就判断 IP 被墙，也不要在原因不明时连续更换 IP。

## 高可用方案思路

可靠方案通常包括独立健康检查、多入口或多中转、受控切换、配置版本记录和回滚路径。具体实现取决于现有拓扑、协议、供应商与风险预算；商业实现不会在本仓库公开。
